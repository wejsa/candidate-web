# candidate-web 디자인 리뷰 — "IT 전문 업체" 방향 전환

> 작성일: 2026-06-06 · 대상: 지원자 프론트엔드 전체 UI · 기준 톤: IT 전문 업체(B2B 테크 벤더/모던 채용 사이트)

---

## 1. 한 줄 진단

지금 디자인은 **"접근성은 만점, 브랜드는 0점"** 상태입니다. WCAG 2.1 AA 파운데이션은 매우 탄탄하지만, 시각적으로는 정부·공공기관 문서 사이트에 가깝고 "IT 전문 업체"의 자신감 있는 인상이 없습니다. 즉 **버릴 게 아니라 그 위에 브랜드 레이어를 올리는 작업**입니다.

---

## 2. 지금 잘 되어 있는 것 (유지 + 확장)

접근성과 구조는 그대로 살려야 합니다. 새 디자인은 이 위에 얹습니다.

- **검증된 대비비 토큰** — `--color-text`(16:1), `--color-text-muted`(7:1), 폼 경계(4.5:1)까지 WCAG 기준으로 계산되어 주석화됨. 컬러를 바꿀 때도 이 대비 검증 방식은 계승해야 함.
- **`:focus-visible` / 터치 타깃(44px) / `prefers-reduced-motion` / skip-link / `visually-hidden`** — 접근성 유틸이 전역에 잘 깔려 있음.
- **디자인 토큰 체계 존재** — `--space-*`, `--shadow-*`, `--radius`가 이미 있어 확장 기반이 됨.
- **CSS Modules 컴포넌트 분리** — 컴포넌트별 스타일 격리가 깔끔해 점진적 리팩터링이 가능함.
- **공고 카드 그리드 + hover lift** — 카드 패턴 자체는 방향이 맞음(다듬기만 필요).

---

## 3. "IT 전문 업체 느낌"이 안 나는 핵심 이유

문제를 영향도 순으로 정리했습니다. 위쪽일수록 "느낌"에 미치는 영향이 큽니다.

### 3.1 브랜드 컬러 부재 — 단일 링크 블루로 모든 것을 처리

`#0066cc`(브라우저 기본 링크색에 가까운 파랑) 하나가 버튼·링크·뱃지·강조에 전부 쓰입니다. 브랜드 컬러도, 세컨더리 액센트도, 제대로 된 뉴트럴 그레이 스케일(현재 `surface`/`surface-2` 2단계뿐)도 없습니다. 테크 회사는 **확신에 찬 고유 팔레트 + 풍부한 그레이 스케일**로 인상을 만듭니다.

### 3.2 타이포그래피가 시스템 폰트

`-apple-system, Segoe UI, Malgun Gothic...` 시스템 스택은 "디자인하지 않은" 느낌의 가장 큰 원인입니다. **폰트 하나만 바꿔도 인상의 절반이 달라집니다.** 한글 채용 사이트는 `Pretendard`(가변, 한/영 통합, 토스·당근 등 다수 채택)가 사실상 표준입니다.

### 3.3 홈이 임시 플레이스홀더

`app/page.tsx`가 "CANDID-001 셋업 검증용 임시 랜딩"입니다. 채용 사이트의 첫인상인데 히어로·가치 제안·CTA가 전무합니다. **랜딩이 없으면 어떤 디테일을 다듬어도 "전문 업체"로 안 보입니다.**

### 3.4 문서형 좁은 레이아웃

전역 `main`이 720~880px로 묶여 있어(블로그/약관 페이지 폭) 제품·마케팅 사이트의 넓고 구조적인 인상이 안 납니다. 게다가 컨테이너 폭이 페이지마다 제각각입니다 — 전역 720/880, `/jobs` 1120, auth 카드 26rem. **통일된 레이아웃 스케일이 없습니다.**

### 3.5 타입 스케일·위계가 얕음

`h1`/`h2`만 크기 지정되어 있고 display·eyebrow·caption 단계가 없습니다. 위계가 평평해서 "정보가 그냥 나열된" 느낌이 납니다.

### 3.6 다크 모드 없음 / 헤더·브랜딩 빈약

모던 테크 사이트의 기본 기대치인 다크 모드가 없습니다(토큰이 CSS 변수라 도입은 쉬움). 헤더는 로고 없이 텍스트 `candidate-web`(플레이스홀더 사명)만 있고, 경계선도 흐린 회색입니다.

## 4. 개선안 (우선순위별)

### P0 — "느낌"을 바로 바꾸는 것 (최소 노력, 최대 효과)

| # | 항목 | 무엇을 | 작업 위치 |
|---|------|--------|-----------|
| P0-1 | **브랜드 폰트 도입** | Pretendard 가변폰트로 교체 (self-host 또는 CDN) | `globals.css` font-family, `layout.tsx` |
| P0-2 | **컬러 토큰 재정의** | 브랜드 컬러 + 9단계 뉴트럴 그레이 + 시맨틱(success/warning/danger) 확장. 기존 대비 검증 방식 유지 | `globals.css` `:root` |
| P0-3 | **타입 스케일 정립** | display/h1/h2/h3/body/sm/xs + weight 2~3단계 + line-height·letter-spacing 규칙 | `globals.css` |
| P0-4 | **레이아웃 폭 통일** | `--container`(예: 1200px) + 섹션/콘텐츠 폭 스케일 단일화 | `globals.css`, 페이지 모듈 |

> P0는 대부분 `globals.css` 토큰 작업이라 컴포넌트 마크업을 거의 안 건드리고도 전 페이지 인상이 바뀝니다(bare semantic HTML + element selector 구조의 장점).

### P1 — 전문 업체의 완성도

| # | 항목 | 무엇을 |
|---|------|--------|
| P1-1 | **홈 랜딩 제작** | 히어로(카피+CTA) → 핵심 직군/팀 소개 → 채용 절차 → 마감 임박 공고 → 푸터 |
| P1-2 | **다크 모드** | `prefers-color-scheme` + 토큰 이중화(light/dark 셋) |
| P1-3 | **헤더/로고/사명** | 실제 브랜드명·로고 적용, 헤더 위계(스크롤 시 그림자 등) 정리 |
| P1-4 | **컴포넌트 디테일** | 버튼 위계/사이즈 변형, 카드·칩·폼 일관 라운드/보더/섀도우 스케일, 아이콘 도입 |
| P1-5 | **푸터** | 현재 전무. 회사 정보/링크/법적 고지 포함한 전역 푸터 |

### P2 — 디테일·정교화

| # | 항목 | 무엇을 |
|---|------|--------|

| P2-2 | **일러스트/그래픽** | empty state·에러·완료 화면용 일러스트 또는 아이콘 시스템 |

## 5. 제안 토큰 스케치 (P0 착수용 예시)

실제 브랜드 컬러는 확정 필요. 아래는 "모던 B2B 테크" 방향의 예시값입니다.

```css
:root {
  /* 브랜드 — 딥 인디고/블루 계열 (신뢰감 + 테크) */
  --brand-600: #2563eb;   /* 주 액션 */
  --brand-700: #1d4ed8;   /* hover */
  --brand-050: #eff4ff;   /* 약배경 */

  /* 뉴트럴 9단계 (현재 2단계 → 확장) */
  --gray-50:#f8fafc; --gray-100:#f1f5f9; --gray-200:#e2e8f0;
  --gray-300:#cbd5e1; --gray-400:#94a3b8; --gray-500:#64748b;
  --gray-600:#475569; --gray-700:#334155; --gray-800:#1e293b; --gray-900:#0f172a;

  /* 타입 스케일 */
  --fs-display: clamp(2.5rem, 5vw, 3.5rem);
  --fs-h1: clamp(2rem, 4vw, 2.5rem);
  --fs-h2: 1.5rem; --fs-h3: 1.25rem;
  --fs-body: 1rem; --fs-sm: 0.875rem; --fs-xs: 0.8125rem;

  /* 레이아웃 */
  --container: 1200px;   /* 전 페이지 통일 */
}
```

> ⚠️ 컬러를 바꾸면 반드시 기존 `globals.css` 주석처럼 흰/검 배경 대비비(AA 텍스트 4.5:1, UI 3:1)를 재검증해야 합니다. 이 프로젝트의 NFR(WCAG 2.1 AA)을 깨면 안 됩니다.

---

## 6. 권장 진행 순서

1. **브랜드 방향 확정** — 사명/로고/주 컬러 1개. (없으면 임시안으로 시작)
2. **P0 토큰 4종**을 `globals.css`에 반영 → 전 페이지 즉시 변화 확인.
3. **홈 랜딩(P1-1)** 신규 제작 → "전문 업체" 인상의 핵심.
4. 다크모드·헤더·푸터·컴포넌트 디테일(P1) 순차 적용.
5. 모션·일러스트·OG(P2)로 마감.

> ack 워크플로우로 진행한다면 위 항목들을 `/skill-feature`로 백로그 등록 → `/skill-plan` → `/skill-impl` 스텝으로 쪼개는 것을 권장합니다. P0는 1~2 스텝, 홈 랜딩은 별도 Task로 분리하는 게 적절합니다.
