# CANDID-010 — 이메일 회원가입 + 이메일 인증 메일 발송

> 소급 작성 문서(CANDID-063). 구현은 완료 상태이며, 본 문서는 요구사항 추적성(DS-07)을 위한 요약·링크다.
> **요구사항 SSOT**: PRD [`docs/sample-requirement.md`](../sample-requirement.md) — **US-AUTH-001 (P0) 이메일 회원가입** (§2.1).

## 연관 사용자 스토리
**US-AUTH-001**: 신규 지원자가 이메일/비밀번호로 회원가입하여 소셜 계정 없이 지원 절차를 진행한다.

## 핵심 요구사항 (PRD 발췌)
- 필수 입력: 이메일, 비밀번호, 비밀번호 확인, 이름, 약관 동의(이용약관·개인정보 처리방침).
- 비밀번호 규칙: 최소 10자, 영문 대/소문자 + 숫자 + 특수문자 중 **3종 이상** 조합.
- 가입 직후 **이메일 인증 메일 발송**. 미인증 상태에서도 로그인·공고 조회는 가능하나, **지원서 최종 제출 시점에 이메일 인증 완료가 강제**된다.
- 가입 성공 시 자동 로그인 후 메인/직전 페이지로 리다이렉트.

## 관련 비즈니스 규칙 / 보안 (CLAUDE.md)
- **BR-AUTH-04**: 이메일 미인증 사용자 — 로그인/조회 가능, **지원서 제출 시점에만** 차단.
- **보안 강제**: 비밀번호는 **BCrypt strength 12** 외 어떤 형태로도 저장/로깅 금지. 평문/로그/응답 노출 금지.
- **BR-PII-01**: 이름 등 PII는 AES-256-GCM 컬럼 암호화 + 응답 마스킹.
- 에러 코드: `USER_EMAIL_DUPLICATED`(이메일 중복), `SYS_VALIDATION_FAILED`.

## 인수 조건
- [x] 가입 성공 시 자동 로그인 + 리다이렉트.
- [x] 비밀번호 BCrypt(strength 12) 해시 저장, 평문/로그/응답 미노출.
- [x] 이메일 중복 시 `USER_EMAIL_DUPLICATED`.
- [x] 가입 직후 인증 메일 **발송 시도**(미수신이 가입 실패로 이어지지 않음 — fail-open).
  - ⚠️ 단, 인증 메일 **전달**은 SMTP 환경 의존: dev는 maildev 로컬 캐처(`:1025`/`:1080`)로 잡히고 실사용자 수신함엔 미도달. 운영 SMTP 미구성 시 인증 링크가 실제로 전달되지 않는다(상세는 [CANDID-020-spec.md](./CANDID-020-spec.md) "현재 한계" 참조).

## 구현 참조
- 상태: **구현 완료**. 후속 보안 강화 — CANDID-036(이메일 인증 race/RL hardening), CANDID-037(RL wrapper 합성 + P2002 정밀 매핑).
- 주요 영역: `app/api/v1/auth/**`, `lib/auth/**`, `lib/email/**`.
- 회귀 가드: `tests/lib/auth/**`.
